# KAN-158 Improve October receipt extraction through one measured cycle

Jira: [KAN-158](https://brownrook.atlassian.net/browse/KAN-158)

## User story

As the person reviewing household receipts, I want more reliable receipt fields
and line items, with unresolved readings clearly flagged, so that I can trust
the ledger and spend less time correcting extraction errors.

## Agreed scope

Complete one improvement cycle and implement, deploy and validate the resulting
general extraction fix and configurable selective vision fallback. Use October
2026 source-folder receipts from both scanned and electronic inputs. Source
month is distinct from purchase date; older purchases and reprints may be present.

Use vision to investigate disagreements with deterministic OCR and parsing.
Verify readings against original receipts before treating them as reference
answers. Improve general rules through a controlled code-fix loop; production
does not edit or deploy its own source. Paul runs application and model commands.

## Acceptance criteria

- [ ] Review the proposed first investigation and measurement plan with Paul
      before implementing it. Select one general failure class.
- [ ] Retain a versioned baseline and source-verified reference labels. Group
      duplicate purchases and reprints before separating development and held-out
      receipts. Record ambiguous fields rather than forcing reference answers.
- [ ] Agree and freeze correctness, regression and fallback gates before the
      held-out evaluation. Numerical targets remain to be agreed.
- [ ] Compare current extraction and vision on matched evidence. Use relevant
      Neo4j lineage and Grafana logs/traces to test explanations; retain actual
      queries, time ranges, versions and outputs privately.
- [ ] Implement a general extraction improvement with synthetic regression
      coverage. Never use receipt-specific filenames, hashes, amounts, addresses
      or expected-value overrides.
- [ ] Measure held-out field and item results against the baseline and agreed
      gates. Record regressions, false acceptance and unresolved/review outcomes.
- [ ] Implement configurable selective vision fallback for the delivered scope,
      preserving review for unsupported or conflicting readings. Measure usage,
      latency and actual GPU execution; do not assume installed models use GPU.
- [ ] Deploy and validate the change, retaining code/PR, configuration and rollback
      references. Explicitly disposition remaining inherited work to follow-ups.

## Definition of done

One complete measured improvement cycle, with its implementation deployed and
validated and its evidence retained. A baseline export or model demonstration
alone does not finish the story. Further improvement cycles remain follow-up work.
